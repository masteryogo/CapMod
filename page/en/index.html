Domain Guardrails

Specialized Agent Toolkit & The Justifier

Generic coding agents running arbitrary Python have no domain guardrails against mistakes that quietly invalidate results. CapTrain provides specialized tools to catch errors before they reach a report.

Block Tools Catches
Data Integrity
check_leakage()
check_split_validity()
check_duplicate_rows_across_splits()
 Leaked targets, wrong split strategy (e.g. random split on temporal data), train/test overlap.
Evaluation Sanity
suggest_metric()
baseline_comparator()
confidence_interval()
 Wrong metric for the problem (e.g. raw accuracy on imbalanced data), unbeaten trivial baselines, noise mistaken for signal.
Diagnostics
learning_curve_analyzer()
feature_importance_sanity_check()
 Overfitting, underfitting, disguised leakage via a dominant or surrogate target feature.
Reproducibility
experiment_diff()
data_version_lock()
 Untraceable run differences, comparisons across mismatched data snapshots, non-deterministic seeds.
Implementation priority: Data integrity and evaluation sanity first — leakage and misleading metrics destroy trust faster than any algorithmic bug, and are the easiest to catch with simple heuristics.
Pipeline Gate — Not Just a Tool

The Justifier

A structured checklist required before reporting any final result. It turns an unearned “94% accuracy” into “94%, and here is why we trust it.”

✓ Split validity verified: zero temporal or group leakage
✓ Metric justified against class imbalance and business payoff
✓ Trivial and heuristic baselines statistically beaten
✓ Duplicate rows & target proxies verified absent

Engineering Discipline

CapTrain thinks like a senior ML engineer

Beyond the core toolkit, these are the 10 requirements that decide whether an ML engineering agent gets trusted in a real production workflow, not just a demo.

01

Cost Awareness

estimate_cost()

Calculates compute and cloud spend before kicking off expensive runs, enforcing a configurable budget ceiling that requires human approval.

02

Slice-Level Evaluation

subgroups by default

Breaks down evaluation metrics by relevant demographic or feature subgroups by default — surfacing hidden performance drops in minority slices.

03

Human-in-the-Loop by Default

mandatory checkpoints

Mandatory approval checkpoints before irreversible steps, such as promoting a model to production, retraining on new data splits, or deleting artifacts.

04

Data Unit Tests

schema + drift checks

Automated schema validation, distribution drift detection, and null-rate assertion tests executed automatically on every dataset or dataset version.

05

Strict Execution Sandboxing

isolated runtime

Isolated execution environment for agent-generated code with strict limits: no unnecessary network access and no file writes outside controlled directories.

06

Existing-Stack Integration

compositional layer

Composes directly with MLflow, DVC, Weights & Biases, Vertex AI, and AWS SageMaker — complementing existing tooling rather than competing.

07

Agent Decision Explainability

reviewable reasoning log

A reviewable reasoning log documenting why specific algorithms, split strategies, or hyperparameters were selected — distinct from post-hoc model explainability (SHAP).

08

Easy Rollback

navigable history

Revert models, datasets, or training configurations to any prior validated checkpoint in seconds with a complete, navigable version history.

09

Post-Deploy Monitoring

drift & degradation

Continuous tracking of data drift, concept drift, latency anomalies, and business metric degradation as an ongoing stage of the ML lifecycle.

10

Multiplayer from Day One

team reviewable

Experiments, rationale logs, and performance metrics are visible and reviewable across the entire team — never locked to a single developer's terminal.
